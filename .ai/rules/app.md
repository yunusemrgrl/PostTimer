# App

## PostTimer 4-domain mimarisi
PostTimer mimarisi 4 bağımsız domenden oluşur: (1) Link Vault — affiliate link/product deposu + URL parser, (2) Post Publishing — medya yükleme + dinamik form (story_link for STORIES, first_comment for REELS/POST/CAROUSEL) + Link Vault eşleştirme (post_id↔link_id), (3) Stock & Price Checker — sadece yayına 15-20 dk kalan postların linklerini tarayan JIT worker + stoksuz/fiyat anomalisinde postu "flagged" moduna çeker, (4) Notification — Telegram bot + event-driven uyarılar + Meta Graph API publisher worker. Geliştirme sırası: 1→2→3→4 (bağımlılık zinciri). Her domain kendi servisi/modeli/testleriyle bağımsız.

## AI localization maliyet konvansiyonu
ElevenLabs ve Gemini ücretli, karakter/çağrı başına faturalandırılır — maliyet bilinçli davran. Varsayılan ElevenLabs TTS modeli `eleven_flash_v2_5`'tir (multilingual_v2'ye göre ~5x ucuz, reels dublaji için yeterli); output format düşük bitrate `mp3_22050_64`'tür. İdempotency zaten duplicate TTS/Gemini çağrısını engeller (retry'da çift ücret yok). Pahalı `multilingual_v2`/yüksek bitrate SADECE kullanıcı açıkça yüksek kalite isterse env ile etkinleştirilir.

## Video dublaj assembly (browser-side Mediabunny)
Dublaj birleştirme (video + TTS ses + opsiyonel altyazı) `resources/js/video-dub.js` içinde **Mediabunny** (WebCodecs tabanlı, MPL-2.0) ile tarayıcıda yapılır; sunucuda FFmpeg YOKTUR (Laravel Cloud serverless). Kaynak video WebCodecs VideoDecoder ile DEĞİL, `<video>` elementinin native decoder'ı ile decode edilir (bazı kaynak codec'ler `undecodable_source_codec` verir — 86b21e6'daki Conversion path bu yüzden geri alındı; hybrid decode follow-up). Encode+mux: WebCodecs H.264 (`CanvasSource`, 2.5 Mbps, keyFrameInterval 2sn, mediaTime tabanlı timestamp — VFR dostu) + AAC (`AudioBufferSource` 128k @44.1kHz stereo) → Mediabunny `Output` + `Mp4OutputFormat({ fastStart: 'in-memory' })` + `BufferTarget` → çıktı **MP4**. Ses pipeline'ı tamamen OFFLINE: `decodeAudioData` (konteyneri çözemezse `AudioBufferSink` fallback; ses yoksa sessiz devam) → `OfflineAudioContext` mix/resample/pad → tek AudioBuffer; realtime audio capture (createMediaElementSource/MediaStreamDestination) YOK. AAC/H.264 encode desteği yoksa `canEncodeVideo('avc')` + `canEncodeAudio('aac')` ile fail-fast — opus fallback YOK (Instagram/iOS AAC ister). Video decode realtime (oynatma) kaldığı için arka plan sekmesi throttle'ı çözülmedi; `stallInterval` eldeki veriyle nazikçe bitirir. Altyazı/overlay burn-in canvas + rVFC döngüsüyle yapılır. ffmpeg.wasm bağımlılığı kaldırıldı (2026-08); geri getirmeyin. mp4-muxer/webm-muxer eklemeyin — Mediabunny aynı yazarın successor'ı ve zaten dependency. Follow-up roadmap: (1) hybrid decode (önce WebCodecs VideoDecoder dene, `undecodable_source_codec`'te `<video>`'ya dön) → realtime 1× darboğazını kaldırır, arka plan sekmesine dayanıklı yapar; (2) AV1 encode olgunlaşınca tercih edilen codec + H.264 fallback (aynı pipeline, config değişikliği); (3) uzun videolarda BufferTarget tüm MP4'ü RAM'de tutar — OOM'da StreamTarget (OPFS/indirme stream) + `encodeFps` göstergesi zaten mevcut. Smoke-test teşhisi (VFR/sessiz/stall/bellek): VFR hız hatasında `ffprobe -show_entries stream=codec_time_base,nb_frames,duration` + `mvhd.timescale` kontrolü — hata muxer'da değil `CanvasSource.add()` timestamp'inde düzeltilir; sessiz video + dub'da çıktıda AAC track + dolu `mdat` doğrula (header'i olan ama sıfır sample'lı track'i bazı playerlar sessizce düşürür — mix dub-only path'ten geçerli AAC frame yazmalı); stall ile kesilmiş MP4'ü Chrome + VLC'de ayrı ayrı aç (VLC reddederse final GOP'ta eksik `stts`/`ctts`); düşük bellekte sabit FPS + artan RAM = `BufferTarget` tek darboğaz (StreamTarget'a geç), FPS de düşüyorsa GC/canvas churn (canvas çözünürlüğünü düşür / encode throttle).
